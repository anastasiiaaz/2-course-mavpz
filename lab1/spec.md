# Сутності, атрибути, ключі

- **Customer** :
  - `customer_id` (`int, PK`) - унікальний ідентифікатор користувача
  - `email` (`string`) - адреса електронної пошти
  - `phone_number` (`string`) - номер телефону
  - `name` (`string`) - ім'я користувача

- **Event** :
  - `event_id` (`int, PK`) - унікальний ідентифікатор події
  - `location_id` (`int, FK`) - унікальний ідентифікатор локації
  - `category_id` (`int, FK`) - унікальний ідентифікатор категорії події
  - `genre_id` (`int, FK`) - унікальний ідентифікатор жанру події
  - `event_date` (`datetime`) - дата проведення події
  - `start_time` (`time`) - час початку події
  - `event_name` (`string`) - назва події

- **Location** :
  - `location_id` (`int, PK`) - унікальний ідентифікатор локації
  - `city` (`string`) - місто
  - `address` (`string`) - адреса
  - `number_of_seats` (`int`) - кількість місць

- **Event_categories** :
  - `category_id` (`int, PK`) - унікальний ідентифікатор категорії
  - `category_name` (`string`) - назва категорії

- **Event_genres** :
  - `genre_id` (`int, PK`) - унікальний ідентифікатор жанру
  - `genre_name` (`string`) - назва жанру

- **Ticket** :
  - `ticket_id` (`int, PK`) - унікальний ідентифікатор квитка
  - `event_id` (`int, FK`) - унікальний ідентифікатор події
  - `customer_id` (`int, FK`) - унікальний ідентифікатор покупця
  - `seat_id` (`int, FK`) - унікальний ідентифікатор місця
  - `ticket_price` (`decimal`) - вартісь квитка на сайті

- **Payment** :
  - `payment_id` (`int, PK`) - унікальний ідентифікатор транзакції оплати
  - `ticket_id` (`int, FK`) - унікальний ідентифікатор квитка
  - `payment_time` (`datetime`) - дата та час проведення платежу
  - `payment_method` (`string`) - спосіб проведення оплати
  - `status` (`string`) - поточний статус платежу
  - `amount` (`decimal`) - фактична сума оплати (з врахуванням комісії, збору за послуги та можливих сертифікатів)

- **Seat** :
  - `seat_id` (`int, PK`) - унікальний ідентифікатор місця
  - `location_id` (`int, FK`) - унікальний ідентифікатор локації
  - `sector_id` (`int`) - номер сектора

# Зв'язки між сутностями:

**`Location` — `Event` (1:N):**

- на одній локації можуть проводитись 0...N заходів, один захід може проходити тільки на одній конкретній локації

**`Location` — `Seat` (1:N):**

- на одній локації є 0...N місць, кожне місце відноситься до однієї конкретної локації

**`Event_categories` — `Event` (1:N):**

- одна категорія може мати 0...N подій, кожна подія відноситься до однієї конкретної категорії

**`Event_genres` — `Event` (1:N):**

- один жанр може мати 0...N подій, подія може мати 0...1 жанр (необов'язкове поле)

**`Event` — `Ticket` (1:N):**

- одна подія має 0...N квитків, кожен квиток належить тільки одній конкретній події

**`Customer` — `Ticket` (1:N):**

- один клієнт може придбати 0...N квитків, кожен квиток належить тільки одному конкретному клієнту

**`Seat` — `Ticket` (1:N):**

- одне місце може бути зарезервоване у 0...N квитках на різні дати, квиток вказує на 0...1 місце

**`Ticket` — `Payment` (1:1):**

- один квиток потребує 0...1 транзакцію оплати, одна транзакція покриває тільки один конкретний квиток

**`Customer` — `Event` (M:N):**

- один клієнт може додати в улюблені 0...N подій, одна подія може бути додана в улюблені 0...N клієнтами

# Критерії прийняття:

1. Усі сутності та зв'язки між ними відповідають вимогам 3NF, атомарності даних та відсутності транзитивних залежностей.
2. Для кожного первинного ключа (PK) використано конвенцію (`<entity>_id`)
3. Усі сутності, назви атрибутів та типи даних повністю збігаються між spec.md та diagram.mmd
4. Усі коміти описані коментарями із дотриманням стандарту conventional commits (`docs`, `fix`).
